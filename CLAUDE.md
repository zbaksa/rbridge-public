# Claude Code working guide — RBridge

This is the **public source repository**, not an authorization credential, not the configured production GitHub Issue carrier, and not proof of an active host deployment.

When using Claude Code to develop RBridge:

1. Follow the existing `AGENTS.md` instructions imported above. Read `README.md`, `SECURITY.md`, `docs/KNOWN_ISSUES.md` and the exact versioned source/design documents relevant to the task before editing code.
2. Work on a dedicated review branch. Use the existing Node 22 lockfile, targeted tests followed by the complete test suite, typecheck, lint, server build, public-source scrub and clean tree. Report results only for the *exact* Git commit tested.
3. A source change, successful CI or merged PR **does not** mean the remote bridge service was restarted, upgraded or granted a new permission. Confirm the installed release and bounded HEALTH receipt through an independently authorized transport.
4. Claude Code can append a visible `Generated by Claude Code` trailer to GitHub Issue bodies. The legacy live V2 protocol parses **pure JSON only**. The Claude fenced-JSON parser in review PR #95 is **opt-in and source-only**, and requires both protocol *and* worker routing; never claim native signed Issue acceptance before a physical release qualification.
5. Do not remove or forge Claude's provenance, use alternative credentials to work around a denial, or treat an error in issue creation as permission to bypass the strict parser.
6. Privileged `RUN_ROOT_SCRIPT` handling is owned by a separate protected root-worker/owner-approval lifecycle, not by a public parser. Require an independently verified per-script owner approval, single-use durable enforcement, protected HOLD/FENCE, exact backups and a fail-closed rollback *before* any privileged live canary or cutover.
7. Preserve durable request identity, the unknown side effects of old jobs and exact historical records. No blind replay and no status inflation: distinguish PASS, FAIL, BLOCKED, UNKNOWN, UNCERTAIN, STALE and NOT_RUN.
8. For connection-specific details use the owner-provided private deployment handoff and authenticated client configuration; do not copy private repo names, tokens, host addresses or restricted state into this public repository.

**Default:** source work is permitted within normal branch/CI authorization. Production activation remains BLOCKED unless a verified, separate host gate explicitly permits it.
