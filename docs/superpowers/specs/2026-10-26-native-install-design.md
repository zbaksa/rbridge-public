# Native V3 configuration installation

The Windows installer always reconstructs V1 configuration. It cannot import the already supported private V3 scope/peer/history configuration and silently removes it on reinstall. Fix this configuration boundary; do not change Chrome production startup or activate a real profile.

Approach selected by the implementer under the user's explicit opt-out of questions: reuse the Native config parser for read-only executable validation, accept an optional complete owner-provisioned V3 config file, and preserve an existing V3 file byte-for-byte. Rejected: duplicating the TypeScript schema in PowerShell; generating pins/empty history; introducing another transport or SSH service.

Add explicit Native CLI `--check-config <absolute-path>`. It reads and validates one private configuration snapshot, prints a bounded JSON receipt with the SHA256 of the same parsed bytes, expected extension id, event root and V3-present flag, and exits without stdin handlers, SSH, runtime initialization or event writes. Other invocation behavior remains unchanged. Refactor the existing loader to expose that same byte snapshot's digest without a second file read.

Windows installer accepts `-V3ConfigFile` containing complete RBRIDGE_NATIVE_HOST_CONFIG_V1 with v3. Validate staged snapshot bytes using the provided Native executable before installation/registry writes. Require the fixed extension id and, for a new V3 configuration, the existing InstallDir/events root. Never invent or change scope/pins/history. Existing V3 config wins; a different explicit candidate is rejected. Keep its raw bytes and event root, require that root already exists, and do not rewrite that config/history. Detect installed config changes before mutations. Fresh V1 installation retains its current behavior. Reject malformed/reparse/oversize inputs and invalid checker receipts.

Qualification: regression-first normal RBridge1027 Node22 CLI tests; actual Windows SEA and installer tests on the existing Windows CI VM, including reinstall preservation and changed-config refusal with file/history/registry readback. The test restores pre-existing HKCU Native-host registration and removes only its own temporary directory. Full Linux and Windows CI, one fresh whole-change review, exact candidate integration. Config validation is not authentication, actual Native connectivity, site qualification or owner acceptance.
