# Admitted Chrome site response reader

Connect the qualified Copy transaction to the existing V3 capture egress through an optional, explicitly configured Chrome reader. Derive the current effect and capture token from the existing runtime/effect store; an internal content hint supplies only its current capture lease token. Never use a content-supplied Markdown string or assistant identity as evidence for this path.

Reuse the existing exact-delivery proof to locate its one user bubble and immediately following completed assistant turn. A self-contained ISOLATED-world probe verifies the exact project URL, last-user adjacency, complete turn state and stable response HTML digest. Chrome supplies the top-frame documentId. Refresh the existing live authority fence, execute the qualified Copy function in MAIN targeted to that documentId, then repeat the ISOLATED proof and live fence before persisting through the existing egress. Refuse wrong profiles, frames, documents, pairing, bytes, authority or changed state. Capture has no SEND operation.

The configured egress exposes a polling operation for this reader and handles the corresponding internal Chrome request. Existing direct V3 notifications and minor-0 startup retain their existing behavior. Coalesce concurrent polls and reuse an already durable capture record before performing another Copy; preserve storage poison and native-forwarding behavior. Reject unresolved historical capture state rather than re-copying it; a matching SEND_VERIFIED history entry is valid pre-capture state. Enforce the configured owner app before acquisition or direct acceptance. Share pending acquisition across egress instances with the same storage authority. Bound the Chrome read transaction to five seconds, including tab reads and admission. A timeout cannot cancel an already queued MAIN injection: stop subsequent transaction steps, quarantine the reader and shared egress against new acquisitions, and never persist a late result. Worker restart is not evidence that an uncertain prior injection was cancelled; reconciliation across worker lifetimes remains part of activation qualification.

An abstract admission callback alone would not close this boundary. The egress must use its real BrowserAuthorityRuntime, reserved RbridgeEffectStore request and ChatgptDeliveryAdapter proof. A new baseline store is unnecessary because the existing proof already identifies the exact current user turn. Global clipboard reads and new controller/transport services remain excluded.

Production startup, Native scope/history/pin provisioning, response lifecycle completion, private app-shell qualification and the availability flag remain separate. This patch supplies the acquisition entry in the existing V3 egress; it does not claim a fully activated Native pipeline or owner Windows acceptance. All fixtures must identify their synthetic DOM/peer scope.
