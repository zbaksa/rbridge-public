# Provisioned V3 extension startup

Finish the missing packaged startup for the already qualified V3 composition. Reuse the one Native/Bridge/controller route. The implementer chooses an explicit V3 build profile with a build-time owner-supplied SHA256 of the complete startup document; the default minor0 package stays unchanged. This is narrower than automatic negotiation or a new provisioning transport.

The V3 package reads a raw JSON string at chrome.storage.local.rbridgeExtensionStartupV3 only after awaited setAccessLevel({accessLevel:'TRUSTED_CONTEXTS'}). Pin its exact UTF8 bytes (2..65536) against RBRIDGE_V3_STARTUP_CONFIG_SHA256 supplied by the trusted release/provisioning process, never from storage or a HELLO claim. Require schema RBRIDGE_EXTENSION_STARTUP_V3 and exactly extensionId, releaseSha, bootstrap, scope, peer, initialHistory, siteAdapter plus schema. Match the fixed extension id and exact compiled release; siteAdapter is CHATGPT_EXACT_COPY_V3. Delegate bootstrap/scope/peer/history/original-ledger validation to startQualifiedExtensionServiceWorkerV3 and use ChromeSiteMarkdownReaderV3. Missing data, access control failure, bad pins or retained history fail before Native connection; never fall back to minor0 or invent an empty history.

The build-time digest is an integrity/trust input from an external provisioner, not proof that an arbitrary document is authenticated. This patch supplies no real owner data, config generator, authority, Native history migration or production install. Extension remote-peer pins are not silently copied from Native config peerPins; their directions differ. A valid package alone does not qualify the owner's private AI UI or activate Linux runtime.

Build profiles v1(default) and v3 use separate dist-extension and dist-extension-v3 outputs. V3 requires its pin; unknown profiles and a V3 pin in a V1 build are errors. Preserve manifest permissions and extension identity. V3 bundles contain only the existing two serialized DOM acquisition functions; artifact verification allows DOM identifiers/selectors only inside those named injection functions. Execute the actual built worker in a document-free VM to prove startup, exact pinned HELLO and closed missing/tampered data; no real AI send.

Use existing isolated worktree, regression-first normal RBridge1027 testing, one fresh component review, full exact-head Linux and Windows CI, and exact tested-source integration. Chrome storage semantics follow https://developer.chrome.com/docs/extensions/reference/api/storage .
